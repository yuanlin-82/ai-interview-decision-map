# Question-Type Matrix

Intent-level only. No spoken examples.

Each type shares the **overview router** (abnormal vs normal).  
Differences live in the **normal strategy pack** and optional **type-specific boundary** notes.

| Type key | Assessment goal | Normal strategy pack (pick ONE family / turn) | Boundary notes |
|----------|-----------------|-----------------------------------------------|----------------|
| `behavioral` | Past behavior as evidence | Ground abstract claims; or deepen episode (clarity / judgment / contribution / reflection) | Hypothetical “I would…” ≠ past episode |
| `situational` | Capability under scenario tension | Past-event deepen; structured plan / trade-off / risk; or anchor empty hypotheses | Don’t chain endless failure “what ifs” |
| `issue-reasoning` | Open-topic critical thinking & argumentation | Construct reasons → deepen one support → counterfactual resilience | Neutral; not a domain quiz; don’t grade “correct answer” |
| `domain-knowledge` | Domain / professional knowledge (spoken technical-style) | Link recall to job use → deepen method → synthesize under a complex case | One proficiency step per turn; not soft behavioral |
| `career-choice` | Career planning maturity | Near-term actions → feasibility → value trade-off under pressure | Process, not “right path” |
| `information-gathering` | Collect & confirm information slots | Confirm admin / experience / preference slots; stop when clear | Not a competency dig |
| `workplace-resilience` | Work-framed stress handling | Emotion handling **or** action logic **or** work-context learning | Non-clinical; workplace frame; soft pass |
| `job-transition` | Leave / job-change drivers | Decision process **or** values **or** patterns across moves | Deflect employer-bashing |
| `culture-fit` | Preference & contribution | Deepen example **or** value trade-off **or** contribution actions | Infer from behavior, don’t checklist values |
| `opening-intro` | Opening narrative | Verify one claim; motivation; distill fit signal | Thin intro → one concrete ask |
| `fallback` | Safe continuation | One 5W1H cell **or** one example request | Prefer continuity over wrong specialty lens |

## How to use this table

- **Product / research:** compare types by *goal* and *probe family*, not by copy.  
- **Implementation:** map each probe family to private templates.  
- **Eval:** score whether the chosen family matched the contract, independent of fluency.  
- **Stem typing:** compliance screen then one primary intent → [type-classification.md](./type-classification.md).
