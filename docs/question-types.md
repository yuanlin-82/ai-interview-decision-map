# Question-Type Matrix

Intent-level only. No spoken examples.

Each type shares the **overview router** (abnormal vs normal).  
Differences live in the **normal strategy pack** and optional **type-specific safety/boundary** pack.

| Type key | Assessment goal | Normal strategy pack (pick ONE probe family / turn) | Type-specific boundary (overview: dashed node) |
|----------|-----------------|------------------------------------------------------|------------------------------------------------|
| `behavior` | Past behavior → future performance | Ground abstract claims in a real episode; or deepen a concrete episode (missing clarity / judgment / contribution / reflection) | — |
| `situation` | Capability boundaries under tension | If past event: deepen decision under constraints; if hypothetical: structure plan / trade-off / risk — without endless “what if it fails” chains | — |
| `opinion` | Stance quality & reasoning | Clarify stance; request reason or example; reconcile internal tension in the argument | — |
| `knowledge` | Concept + applied use | Explain / apply / contrast terms; recover from “don’t know” via adjacent knowledge without humiliation | — |
| `career` | Decision process, not “right path” | Motivation & self-awareness; or preparation & actionability of the choice | — |
| `information` | Complete & confirm facts | Fill missing slot; disambiguate; confirm suspected ASR value — then stop when complete | Low-friction confirmations; avoid drilling answered slots |
| `mentalhealth` | Workplace resilience (non-clinical) | Emotion awareness / coping action / learning — always work-framed | Redirect non-work trauma; do not diagnose; allow soft pass |
| `stability` | Drivers of transitions | Decision process; values; patterns across moves — neutral tone | Deflect employer-bashing into environment-fit without moralizing |
| `culturefit` | How they work with others / environments | Concrete preference via past scenes; trade-offs; contribution style | Don’t solicit “guess our culture”; keep focus on candidate’s examples |
| `selfintroduction` | Claims, motivation, clarity | Verify a claim; probe motivation; distill core fit signal | Thin intros → request role-relevant experience (still one ask) |
| `default` | Clarify when no specialty model fits | One 5W1H deepening **or** one example request; stay neutral-curious | — |

## How to use this table

- **Product / research:** compare types by *goal* and *probe family*, not by copy.  
- **Implementation:** map each probe family to private templates.  
- **Eval:** score whether the chosen family matched the labeler’s contract, independent of fluency.
